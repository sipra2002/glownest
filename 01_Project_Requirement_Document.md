> **GlowNest – AI-Powered Skincare & Beauty Platform** | PERN Stack (PostgreSQL, Express.js, React.js, Node.js, all TypeScript) | AI: Demo Mode (Phase 1)

# 1. Project Requirement Document

## 1.1 Purpose
GlowNest helps users understand their skin, identify visible skin concerns, and receive personalized skincare routines and product recommendations, with an integrated e-commerce store and educational blog.

## 1.2 Goals
- Deliver a premium, modern beauty-startup experience (not a generic template).
- Provide a guided skin analysis flow (photo upload **or** quiz) producing a personalized report.
- Convert analysis results into an actionable AM/PM routine and shoppable products.
- Let users track skin progress over time and compare reports.
- Be honest and transparent: results are **cosmetic assessments, never medical diagnoses**, and demo results are never presented as real AI output.

## 1.3 Target Users
| Persona | Need |
|---|---|
| Skincare beginner | Doesn't know skin type; wants a simple routine |
| Concern-driven shopper | Acne, pigmentation, dryness; wants targeted products |
| Routine optimizer | Wants to track progress and compare results |
| Casual browser | Reads articles, browses store |

## 1.4 Design Requirements
- **Palette:** soft cream, white, blush pink, sage green (with a matching dark mode).
- **Typography:** elegant serif for headings (e.g., Playfair Display / Cormorant), clean sans for body (e.g., Inter / DM Sans).
- Rounded cards, subtle shadows, smooth transitions (Framer Motion), minimal layouts.
- Mobile-first, WCAG 2.1 AA contrast and keyboard accessibility.
- Professional product imagery (sample seed images; replaceable via CMS/admin).

## 1.6 Non-Functional Requirements
| Category | Requirement |
|---|---|
| Performance | LCP < 2.5 s on 4G; API p95 < 500 ms (excluding AI call); lazy-loaded images/routes |
| Availability | 99.5% target (free/low tier hosting caveat: Render cold starts) |
| Scalability | Stateless API; horizontal scale; image storage off-server |
| Accessibility | WCAG 2.1 AA |
| Responsiveness | Mobile-first (360 px+) |
| Browser support | Last 2 versions of Chrome, Safari, Firefox, Edge |
| Maintainability | TypeScript strict mode, ESLint/Prettier, tests, clean folder structure |
| Observability | Structured logs, error tracking (Sentry), health endpoint |
| UX states | Every data view has loading, error, and empty states |
| Privacy | Data minimization, user-controlled deletion, explicit consent |

## 1.7 Development Requirements (from brief)
- Reusable React components; TypeScript types/interfaces throughout.
- Frontend and backend in separate packages.
- Secrets via environment variables (`.env.example` provided).
- Sample seed data (products, reviews, articles, testimonials).
- **No placeholder buttons or dead links**; every nav item and button performs a real action or routes to a real page.

## 1.8 Out of Scope (Phase 1)
- Real AI inference (architecture ready; provider added later)
- Real payment processing and tax/shipping integrations
- Native mobile apps
- Medical diagnosis or disease detection (never in scope)

## 1.9 Acceptance Criteria (summary)
1. A new user can register, complete consent, upload an image (or take the quiz), and view a report with the disclaimer and demo banner.
2. Report → routine → add to cart → demo checkout works end to end.
3. Dashboard shows history and compares two reports.
4. Store search/filter/cart/wishlist/reviews work.
5. Lighthouse ≥ 90 (Performance/Accessibility/Best Practices) on key pages.
6. No simulated result is ever unlabeled.
